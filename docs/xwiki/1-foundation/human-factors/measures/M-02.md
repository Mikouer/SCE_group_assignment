# M-02: Reminder success rate

| Field | Description |
| --- | --- |
| ID | M-02 |
| Name | Reminder success rate |
| Status | In Progress |
| Evidence basis | Bespoke behavioural measure derived from the failed alarms and notes in [SA-01](../../operational-demands/activities/SA-01.md). |
| Construct measured | Whether a reminder helps Cleber ([ST-01](../../operational-demands/stakeholders/ST-01.md)) initiate the eating activity. |
| Type | Quantitative. |
| Instrument or procedure | For each reminder episode, the observer and the prototype log record the reminder number (1 to 3), the time of the reminder, and the response. Each response is coded as one of: **eating started**, **refusal or postponement**, **no response**, or **uncertain** (activity that does not show whether he is eating). Eating started counts only if it happens within the response window. In the current cycle the person playing Cleber reacts to a situation card (for example asleep in another room, or not hungry) and the observer codes what he does; the outcome is not scripted in advance. |
| Scoring or coding scheme | **Initial-reminder success rate** = first reminders followed by *eating started* within the response window, divided by all first reminders given. **Follow-up rescue rate** = episodes whose first reminder was unsuccessful and that end in *eating started* after a follow-up, divided by all episodes whose first reminder was unsuccessful and that received a follow-up. A postponement is its own category, neither success nor failure; the restarted sequence is recorded as a linked episode. *Uncertain* is never counted as success. Missing observations are excluded from the denominator and reported separately. **Response window (proposed starting value): 10 minutes after a reminder**, matching the interval used in [TECH-02](../../technology/TECH-02.md) and to be tuned in the evaluation. |
| Validity and reliability | Bespoke. A response does not establish why a reminder succeeded or failed, and a response alone is not proof of eating. Cleber saying he is done marks the meal as done, but he is never required to say it. With a person role-playing Cleber, the measure shows how the interaction works for that person, not how someone with dementia would behave. |
| Serves | Validation. |
| Burden | Low when the prototype log records the events; moderate when an observer must code responses directly. |

Used by [EM-01](../evaluation-methods/EM-01.md) and associated with [HFC-01](../concepts/HFC-01.md). It operationalises
[UC01-F1-CL1](../../../2-specification/use-cases/uc01/UC01-F1-CL1.md) (initial-reminder success rate) and
[UC01-F2-CL2](../../../2-specification/use-cases/uc01/UC01-F2-CL2.md) (follow-up rescue rate). The contextual limitations are
discussed in the [evaluation discussion](../../../3-evaluation/DiscussionAndLimitations.md).
