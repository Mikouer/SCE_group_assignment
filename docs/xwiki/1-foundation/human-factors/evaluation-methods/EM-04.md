# EM-04: Cognitive walkthrough

| Field | Description |
| --- | --- |
| ID | EM-04 |
| Name | Cognitive walkthrough |
| Status | In Progress |
| Evidence basis | Standard formative inspection method used in human-computer interaction: a step-by-step simulation of a persona's mental model, using the four-question baseline procedure from the Usability Body of Knowledge. Evaluating SCE Use Cases this way suits SCE because the Action Sequence, persona, Premises and Claims already exist. No session has been held yet. |
| Procedure summary | Evaluators (ideally three to five) step through the Action Sequence of [UC01](../../../2-specification/use-cases/uc01/UC01.md) from the point of view of a persona. A facilitator introduces the Use Case, its objective and the persona, then shows the artifact one step at a time and does not intervene or explain problems away. At each step the evaluator answers four questions and justifies each answer: (a) Will the user try to achieve the right effect? (b) Will the user notice that the correct action is available? (c) Will the user associate the correct action with the effect they are trying to achieve? (d) If the correct action is performed, will the user see that progress is being made? Success stories, failure stories and design suggestions are written on a standard form. Afterwards the evaluators answer a few open-ended questions about one Claim. |
| Purpose | Formative. It addresses Premises (does the Action Sequence work as specified from the persona's point of view?) and, through the follow-up questions, one Claim. The method is typically validation-leaning in SCE (can the persona plausibly reach the intended effect). |
| Human subjects required | Yes: evaluators and a facilitator. |
| Measures used | [M-04](../measures/M-04.md) (whether each step works as specified, judged from the walkthrough answers) and the open question of [M-03](../measures/M-03.md) for [UC01-F2-CL3](../../../2-specification/use-cases/uc01/UC01-F2-CL3.md). |
| Cost and feasibility | Low: a representation of the interface, a persona, a task list with the Action Sequence, a problem-reporting form and a few evaluators. |
| Known limitations | It only surfaces problems within the scripted Action Sequence, and gives no reliable estimate of how frequent or severe a problem is. It assumes the evaluators can simulate the persona, which is hard for someone with dementia. Only human-facing steps can be walked. It does not test real sensors, timing or logging. |

Applied in [ER-01](../../../3-evaluation/reports/ER-01.md).
