# EM-05: Meal-status and alert verification

| Field | Description |
| --- | --- |
| ID | EM-05 |
| Name | Meal-status and alert verification |
| Status | Not Started |
| Evidence basis | Bespoke candidate procedure addressing the detection and delayed-awareness breakdowns in [PS-01](../../operational-demands/problem-scenarios/PS-01.md). No completed study is supplied. |
| Procedure summary | Before testing, define the meal observation window, missed-meal decision rule and alert observation window. Observe completed meals, missed meals and ambiguous situations using the intended sensing setup. An independent observer records actual consumption, including portions remaining and food discarded, transferred or shared. Compare the system's meal-status judgement with that record using [M-06](../measures/M-06.md), and check plate-based intake estimates against observed consumption as described in [M-01](../measures/M-01.md). Record unknown outcomes. For situations requiring escalation, use [M-07](../measures/M-07.md) to record when the escalation condition is met and when the alert appears on the recipient's interface. Staged alerts can be used for the delivery check. |
| Purpose | Verification of meal-status detection and alert delivery, with a reference check for the intake estimates used by M-01. |
| Human subjects required | Yes for actual-consumption observations, with consent. The delivery check can use staged events and an evaluator-operated receiving interface. |
| Measures used | [M-06](../measures/M-06.md), [M-07](../measures/M-07.md), and the intake-reference procedure described in [M-01](../measures/M-01.md). |
| Cost and feasibility | Moderate for meal observation: requires an observer, meals and the intended sensing setup. Low for staged delivery checks with working sender and receiver interfaces. |
| Known limitations | Candidate for a later evaluation. The current walkthrough supplies no real meal, sensor or delivery-time evidence. Observation can affect behaviour, ambiguous intake limits the reference record, and delivery results depend on the tested channel and network. Acceptance thresholds require agreement before pass/fail conclusions. |

This procedure examines meal-status detection for [F2](../../../2-specification/use-cases/uc01/F2.md) and alert delivery for [F3](../../../2-specification/use-cases/uc01/F3.md). Delivery findings provide supporting evidence for [UC01-F3-CL4](../../../2-specification/use-cases/uc01/UC01-F3-CL4.md).
