# EM-03: Scenario-based prototype verification

| Field | Description |
| --- | --- |
| ID | EM-03 |
| Name | Scenario-based prototype verification |
| Status | In Progress |
| Evidence basis | Candidate verification method (staged, log-based testing against a specification) derived from the need to show that the prototype follows the specified [UC01](../../../2-specification/use-cases/uc01/UC01.md) behaviour. No completed protocol is supplied. |
| Procedure summary | Run a fixed set of scripted scenarios on the [AT-01](../../../3-evaluation/artifacts/AT-01.md) prototype, with the facilitator selecting the meal-state events: (1) eating confirmed after the first reminder (by the camera, or because Cleber says he is done); (2) refusal, one postponement, restart from the first reminder; (3) a second postponement attempt, which must not reset the sequence; (4) no response through three reminders, with no kitchen activity so the camera stays off, then an alert to Sarah; (5) kitchen activity with no confirmation of eating, which must be logged as unconfirmed; (6) the camera sees the plate leave the table and return, with the away time logged and no reminder sent meanwhile (and a variant in which the plate never returns, which is logged as not returned with no alert); (7) Sarah does not respond, so the alert is repeated once and then Gilbert is notified; (8) eating confirmed after escalation, which gives a resolved update; (9) a sensor reported offline, which the summary must show as missing data. Compare the prototype's event log with the specified Action Sequence and Verification Criteria. |
| Purpose | Verification. |
| Human subjects required | No. |
| Measures used | [M-04](../measures/M-04.md). |
| Cost and feasibility | Low: the prototype, a scenario script and an evaluator. |
| Known limitations | Verifies the prototype's scripted logic only. Because the facilitator supplies the meal-state events, it does not establish the accuracy of real sensors or the camera, speaker coverage across rooms, real timing in a home, or any effect on a person. |

Not applied in the current cycle: it needs a working prototype with an event log. [EM-04](EM-04.md) is used instead for the walkable steps.
